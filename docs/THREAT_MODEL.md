# 威胁模型

> 1.3 / alpha.9（2026-11-07）：新增风险为跳过首章计划、把建议冒充作者指令、无界返修/计费、旧任务静默扩大授权、修订后旧报告仍有效、目录重排损坏稳定身份。逐章完整结构化计划、用途/角色绑定、每章两轮返修及运行请求上限、旧任务显式升级、来源版本比较/不可变结果和旧稿、作者指令独立日志降低这些风险。聊天和副本只读提示不是 OS 权限；正式大纲与 Canonical 始终经既有精确批准。重规划使旧审稿失效，旧证据保留；目录调整只改变阅读归属，不直接重编号正式作品。合成模型不能证明真实模型会遵循计划或作出正确文学判断，未知结果不自动重试，宿主/同账户其他程序及历史原生崩溃的限制不作消除承诺。

> 1.2.7 大纲优先修正 / alpha.7：把全局建议当作硬约束会迫使作者改写已确认规划；自动元数据也可能误覆盖作者标题、提早结束八卷故事或重复分配编号。执行目录与正式大纲分离、已命名来源锁定、本地稳定 ID/事务、明确卷章范围、已声明后续卷不因模型单次“完结”被跳过，以及有限请求上限降低这些风险。模型的完结/卷名仍是建议，不能证明叙事质量或真实完结；没有改动作者批准、文件边界或模型权限。真实模型对新字段遵循程度未测，不把合成通过当作真实成功。

> UI 2.0 / Phase 1.2.7：风险包括状态摘要误导、旧范围批准仍有效、隐藏低频入口后误以为权限改变、动画/后台回调访问已关闭对象，以及把显示缩放测试冒充真实用户验收。界面从原状态投影，修改启动范围重新核对并清除勾选，歧义大纲范围不自动扩大，已有报告/源稿核验 SHA 后展示；没有新的 Model/Bridge 写入授权。Qt 对象拥有动画/计时器，嵌入导出复用主任务守卫。最近作品和偏好是本机敏感信息；同账户其他进程的访问、先前未定位原生进程崩溃、真实 IME/用户验收限制继续保留。

> Phase 1.2.6 增量：模型响应/规划/指导/项目元数据仍不可信。流水线步骤、有限范围、配置绑定、请求/响应 SHA 及幂等产物降低重放/串用风险，但远端响应丢失仍可能收费，不能保证远端恰好一次。审稿引文核对不证明推论正确，严重风险交作者裁决；旧稿不自动返工。批次是可恢复顺序提交，不是跨文件原子事务。恢复锁须确认进程结束并匹配记录，旧格式/未知归属保留。GUI 调度绑定窗口生命周期，关闭不后台继续；这不是同账户恶意程序或 OS 级隔离。

> Phase 1.2.5 当前补充：参考资料、模型输出、历史记录和项目配置均视为不可信输入。抽象风格分析的独立模型任务不提供文件/Shell/网络工具，API 只交付一个已注册结果。导出只由作者界面触发，绑定选定版本、复核哈希、不覆盖目标。官方 Pandoc 独立程序固定 SHA/参数、JSON AST、干净环境、sandbox/超时/堆限制；不启用 server/Lua/过滤器/外部 PDF engine，唯一图像是作者选定 PNG。该限制不是 OS 级网络隔离或第三方完整审计。追加对话和分析正文仍为本机私人数据，同账户其他进程可访问；跨项目切换保护未发送内容。安装器仅显式扩大已校验二进制复制上限至 256 MiB，小说默认上限仍 4 MiB。费用只按来源明确的作者价格和可解释用量估算，未知不作免费，不能当账单。

> Phase 1.2.5 当前开发补充：新增边界为作者 Qt 界面 → 本机安全凭据引用 → 官方 SDK → 固定供应商模型接口，以及原生工具调用 → 角色固定 Broker → Core。项目内容/模型调用不获凭据、Shell、任意文件/网络或作者晋升权限。拒绝自定义目标、重定向、未知路径与未注册工具；一次明确 SDK 推理只允许一次 POST，禁用自动续接、隐式预热和收费重试。项目文件中的配置不能替代本机作者发送授权。供应商/同 Windows 用户恶意进程/管理员、Python 字符串内存残留、网络超时后可能计费等风险不在完整保证范围。SDK 及依赖不是全闭包安全认证；实际 API 权限/多轮/缓存测试因负责人暂缓而 SKIPPED。增量审查与证据。

## 资产与信任边界

资产：私人正文/正典、作者批准范围、人物知识与伏笔记录、用户规则、模型凭据、账号和设备配置。边界：公开上游→审查暂存→插件只读安装树→指定作品根→宿主/模型服务。模型凭据从不进入 Novel Studio。

| 威胁 | 路径 | 缓解 | 剩余限制 / 验收 |
|---|---|---|---|
| 供应链注入 | 上游 Skill 要求运行安装器/上传或动态下载 | 固定 commit、逐文件白名单、哈希、保留原文/许可；禁止自动下载执行 | 哈希证明版本一致，不证明作者善意；人工审查 |
| 提示词注入 | 正文或第三方 reference 含命令 | 正文当数据；wrapper/角色边界；Editor 声明只读工具，另需显式 CLI deny 会话规则 | 模型服从度不可只靠静态测试保证 |
| 数据外泄 | 网络库、Shell、MCP、日志 | 本地运行期无网络/子进程；Editor 禁继承 MCP；不记录正文 | 宿主可能发送模型上下文，须向用户说明 |

## 攻击者与假设

考虑恶意/受侵上游、文本注入、误操作、路径配置错误、并发写入者；不假设可抵御设备管理员、被入侵宿主或模型供应商自身的数据行为。工程目录需由用户信任；本地原型仅防常见路径错误与静态可识别行为。

## 验证策略

代码静态检查、来源哈希、依赖白名单、路径越界/符号链接合成测试、中文只读功能测试、Editor 权限检查和人工审查分别给结论。完整模型创作链和 OS 沙箱隔离必须在宿主中验收，不能以代码门禁替代。


## Phase 1.2 当前权限结论（2026-11-04）

CLI 1.5.0 的显式会话 deny 已取得实际工具拒绝事件；仅列草稿 allow 不会关闭工作区其他默认写权限。原角色继续聊天交付，不开放自动写入。新增 assets/permissions/read-only-session.json，必须通过 --settings 主动加载；安装不自动应用，不修改全局配置。宿主权限检查不是 OS 隔离，提示词、Git 与备份也不是。定稿、世界观、人物与重要追踪改动必须逐次明确人类批准。

只用合成数据测试；无私人小说、密钥或账号数据进入证据。无新增依赖、网络连接、代理/中转、Hooks 或后台服务。宿主 AI 仍按 Antigravity/模型供应商政策处理上下文；不声称整个流程离线。真实权限证据、失败和未测范围以源码仓库的 docs/PHASE1_2_PERMISSION_AUDIT.md 和 docs/PHASE1_2_FINAL_REPORT.md 为准；审计原始证据不随运行包分发。上文早期阶段待办是历史记录。
